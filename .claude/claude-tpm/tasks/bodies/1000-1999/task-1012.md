# #1012 · Harden e2e runner against order-dependent timing flakiness

- **State:** open
- **Created:** 2026-10-02

**Context:** Timing-sensitive e2e tests (copy-icon ~1s revert, localStorage persistence, color-designer accordion) intermittently fail with ~30-38s timeouts in FULL serial test-all.mjs runs but pass clean in isolation. Order-dependent: tools run ~3x slower after the big color-designer suite (color-picker 1.1m in-sequence vs 23s isolated) — resources (Chromium processes/handles) likely not fully released between per-tool suites. color-designer self-heals via its `retries`; most tools have retries:0 so one timeout fails the suite. Candidate fixes (runner robustness, NOT tool behavior): (1) standardize retries:1 in src/lib/test-support/playwright.base.config.mjs keeping workers:1/fullyParallel:false; (2) ensure each `npm run test:e2e` fully tears down Chromium before the next starts. Not a regression — all tools pass in isolation, builds byte-identical. Surfaced during #1008 Phase 1/2 verification 2026-10-02.
